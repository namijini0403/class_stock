## 결정 목록

### 학생 상태는 서버측 Postgres JSONB가 정본 (2026-08-15, 사용자 명시)
- 결정: 학생 상태(잔액·보유 종목·거래 이력 등)의 정본은 서버 Postgres DB(JSONB 컬럼)다. 클라이언트 localStorage/IndexedDB 저장은 정본이 아니며 캐시일 뿐.
- 이유: Railway 배포 전환의 핵심 목적 — 여러 기기·브라우저에서 동일한 학생 상태를 신뢰성 있게 공유하고, 서버측 트랜잭션(`SELECT ... FOR UPDATE`)으로 동시 거래 경쟁 조건을 막기 위함.
- 영향 범위: `server.js`(라우팅·거래로직), `lib/db.js`(스키마), 학생 상태를 다루는 모든 API 엔드포인트.
- 폐기 조건: 없음 (아키텍처 전환의 근간).

### 의존성은 pg 하나만 (2026-08-15, 사용자 명시)
- 결정: npm 의존성은 `pg`(node-postgres) 하나만 유지한다. 새 의존성 추가 금지 — Node 내장 모듈(crypto/http/fs)로 해결.
- 이유: 순수 Node.js·프레임워크 없음이라는 프로젝트 정체성 유지. 공급망 취약점 표면 최소화(교육기관용 앱의 보안 요구사항).
- 영향 범위: `package.json`, 전체 서버 코드.
- 폐기 조건: 사용자 재승인 없이는 변경 불가.

### 학급 코드/닉네임/PIN 인증 방식 (2026-08-15, 사용자 명시)
- 결정: 학생 로그인은 학급 코드(class_code) + 닉네임(nickname) + PIN(scrypt 해시 저장) 조합으로 한다. 실명·학번 등 개인정보는 수집하지 않는다.
- 이유: 초등학생 대상 서비스의 개인정보 최소 수집 원칙. 닉네임+PIN만으로 간편하게 접속 가능해야 함.
- 영향 범위: `lib/db.js`(students/classes 스키마), `lib/auth.js`, `server.js` 로그인 라우트, `public/app.js` 로그인 UI.
- 폐기 조건: 없음.

### 운영 환경 fail-closed (2026-08-15, 사용자 명시)
- 결정: 운영 환경(NODE_ENV=production)에서 JWT_SECRET(32자 이상)·DATABASE_URL 등 필수 환경변수가 없으면 서버는 기본값으로 대체하지 않고 즉시 종료(exit 1)한다.
- 이유: 약한 기본값·비밀 누락 상태로 조용히 기동되는 것을 방지 — 학생 계정·잔액 데이터의 무결성 사고 예방.
- 영향 범위: `server.js` 부팅 시퀀스(`ensureEnv`/`loadEnv` 이후 검증 블록), `lib/auth.js`.
- 폐기 조건: 없음.

### JWT_SECRET 운영 중 회전 금지 (2026-08-15, 사용자 명시)
- 결정: 운영 중인 JWT_SECRET을 임의로 회전(교체)하지 않는다.
- 이유: 회전 시 발급된 모든 토큰이 무효화되어 전 사용자(학생·교사)가 강제 로그아웃된다 — 수업 중 서비스 중단으로 이어짐.
- 영향 범위: `lib/auth.js`, Railway 환경변수 운영.
- 폐기 조건: 보안 침해로 즉시 회전이 불가피한 경우에만, 사용자 승인 후 전 사용자 재로그인 공지와 함께 진행.

### `.stocksave` 백업 형식 폐지 (2026-08-15, 사용자 명시)
- 결정: 기존 클라이언트 로컬 AES-GCM 암호화 + `.stocksave` 백업 파일 다운로드 기능은 v3(Postgres 전환)에서 사용을 종료한다. 상태는 서버가 정본이므로 로컬 백업 파일 복원 경로가 더 이상 필요 없다.
- 이유: 서버측 JSONB 정본 결정과 상충 — 로컬 백업이 서버 상태와 어긋나면 혼란만 유발.
- 영향 범위: `public/app.js`(백업/복원 버튼·`indexedDB`/`crypto.subtle` 사용 경로), `README.md`.
- 폐기 조건: 없음(제거가 최종 형태).

### 학생 상태 테이블은 정규화 대신 JSONB 컬럼 하나 (2026-08-15, 사용자 명시 — Task 2 브리프)
- 결정: `students.state`는 정규화된 holdings/transactions 테이블 대신 JSONB 컬럼 하나로 저장한다.
- 이유: `applyTrade`·`applyCorporateActions`·`applyTeacherCommands` 세 상태 엔진이 상태 객체 전체를 `structuredClone`으로 소비·반환하도록 이미 짜여 있다. JSONB 컬럼이면 load→apply→save 트랜잭션으로 세 엔진을 그대로(수정 없이) 재사용할 수 있다. 정규화하면 세 엔진 전부를 다시 쓰고 다중 테이블 트랜잭션 쓰기를 도입해야 하는데, 교실 규모(학급당 최대 약 40명, 상태 크기 최대 약 1MB, 거래 1500건 상한이 이미 있음)에서는 쿼리 이득이 전혀 없다. 명렬 요약은 Node에서 한 학급 분 행만으로 계산하고, 단일 행 `SELECT ... FOR UPDATE`가 학생별 직렬화를 공짜로 제공한다.
- 영향 범위: `lib/db.js`(students 스키마), `server.js`의 거래·기업행동·교사명령 엔드포인트(Task 5+).
- 폐기 조건: 학급 규모가 크게 늘거나(예: 학교 전체 동시접속) JSONB 행 단위 잠금이 병목이 되면 재검토.

### 교사 로그인은 개인 비밀번호 OR 학교 공통 초기 비밀번호 (2026-08-16, 사용자 명시)
- 결정: `TEACHER_MASTER_PASSWORD`(선택, 8자 이상)를 설정하면 모든 담임 교사 계정이 개인 비밀번호와 학교 공통 초기 비밀번호 둘 다로 로그인할 수 있다(관리자 계정은 제외, ADMIN_PASSWORD만 사용).
- 이유: 담임 교사가 개인 비밀번호를 분실했을 때 관리자 개입 없이 즉시 복구하기 위함 — 사용자 지시.
- 영향 범위: `server.js`(`/api/teacher/login`, `/api/teacher/password`), `public/teacher.html`·`teacher.js`(비밀번호 변경 UI), `.env.example`, `README.md`.
- 폐기 조건: 없음.

### 국내 주식 전용·공공데이터 사용 (2026-08-18, 사용자 명시 — 확인 주기는 2026-08-21에 대체)
- 결정: 종목·시세·거래·학생 화면을 국내 6자리 종목코드와 원화 가격만 사용하는 단일 시장 구조로 운영한다. 금융위원회 공공데이터포털의 주식시세정보를 단일 공식 시세 경로로 사용한다.
- 이유: 사용자가 보유한 공공데이터포털 키를 사용해 수업 운영을 단순화하기 위함.
- 영향 범위: `server.js`, `lib/market-data.js`, `lib/universe.js`, 종목 캐시, 학생·교사 시장 UI, 환경 예제와 운영 문서.
- 폐기 조건: 국내 전용·단일 공식 공급자 결정은 유지한다. 기존의 짧은 확인 주기만 아래의 일별 OHLCV 결정으로 대체한다.

### 금융위원회 일별 OHLCV·하루 1회 확인·일봉 차트 (2026-08-21, 사용자 명시 및 공식 명세 확인)
- 결정: 가격과 차트의 정본은 금융위원회 `주식시세정보`의 일별 OHLCV(시가·고가·저가·종가·거래량)다. 서버는 한국시간 14:10에 새 공식 자료를 하루 1회 확인하고 일시적 오류는 30분 뒤 제한적으로 재시도한다. 종목 상세 차트는 최근 30·90·180일 범위의 일봉으로 제공하고 휴장일에는 봉을 만들지 않으며, 시간봉이나 장중 실시간 차트로 표시하지 않는다.
- 이유: 공식 데이터는 일별 자료이며 기준일 다음 영업일 오후 1시 이후 반영될 수 있다. 제공되지 않는 장중 가격을 추정하거나 같은 일별 값을 시간봉처럼 반복하면 학생에게 잘못된 시장 정보를 주게 된다.
- 영향 범위: `lib/market-data.js`, `server.js`, 일별 시세 캐시, 차트 API와 학생 UI, `.env.example`, `README.md`, 검증 스크립트.
- 폐기 조건: 학생 대상 화면 제공 권한까지 확보한 공식 장중 시세 공급자를 사용자가 별도로 승인할 때만 재검토.

### 국내 전용 신규 상태 모델로 시작 (2026-08-18, 사용자 명시)
- 결정: 아직 배포하거나 학생이 사용하지 않았으므로 과거 시장 상태를 이관하지 않는다. 학생 상태·보유·거래·기업행동·시세는 국내 6자리 코드와 KOSPI·KOSDAQ·KONEX만 허용하는 현재 스키마로 새로 시작한다.
- 이유: 실제 학생 장부가 없으므로 이전 형식을 지원하는 정리 계층보다 국내 전용 허용목록이 더 단순하고 안전하다.
- 데이터 기준: 학교 서버 배포에는 새 빈 Postgres를 사용한다. 사용하지 않는 로컬 구버전 상태 파일과 로그는 삭제하며 운영 DB에 가져오지 않는다.
- 영향 범위: `server.js`, `lib/domestic.js`, `lib/market-data.js`, `lib/universe.js`, 학생 상태 응답, 종목 캐시와 국내 전용 회귀검사.
- 폐기 조건: 사용자가 다른 시장을 다시 승인할 때만 재검토.

### 학생 내역은 Railway Postgres에 저장 (2026-08-18 결정, 2026-08-21 배포처 확정)
- 결정: 학생 내역은 로컬 JSON 파일이 아니라 Railway 프로젝트의 Postgres에 저장한다. 애플리케이션 서버와 배포도 Railway를 사용한다.
- 이유: 여러 기기에서 동일한 학생 계정과 투자 내역을 사용하고 서버측 트랜잭션으로 무결성을 지키기 위함.
- 영향 범위: Postgres JSONB/JWT 구조를 사용하며, `lib/db.js`·`lib/auth.js`·Railway 구성을 로컬 저장 방식으로 되돌리지 않는다.
- 폐기 조건: 없음.

### Railway 비밀값 관리와 버전별 안전 배포 (2026-08-21, 사용자 요청)
- 결정: `DATABASE_URL`, JWT 비밀키, 관리자·교사 비밀번호, 공공데이터 API 키는 Railway Variables에서만 관리한다. API 키·학생 데이터·시세 캐시는 Git과 전달 ZIP에 넣지 않는다. 매 버전은 전체 테스트와 비밀값·추적 파일·ZIP 보안검사를 통과한 뒤, 출시 대상 파일 경로만 명시적으로 스테이징하여 `main`에 푸시한다.
- 이유: 공개 저장소나 전달 파일을 통한 비밀값·학생 내역 유출을 막고, 관계없는 로컬 파일이 한꺼번에 배포되는 것을 방지하기 위함.
- 영향 범위: Railway Variables, `.gitignore`, `.dockerignore`, staged-file 보호 훅, 검증 스크립트, Git 커밋·푸시 및 ZIP 생성 절차.
- 폐기 조건: 없음. 배포 플랫폼이 바뀌어도 비밀값·학생 데이터·캐시 제외와 명시적 파일 스테이징 원칙은 유지한다.

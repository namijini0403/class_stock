## 결정 목록

### 학생 상태는 서버측 Postgres JSONB가 정본 (2026-08-15, 사용자 명시)
- 결정: 학생 상태(잔액·보유 종목·거래 이력 등)의 정본은 서버 Postgres DB(JSONB 컬럼)다. 클라이언트 localStorage/IndexedDB 저장은 정본이 아니며 캐시일 뿐.
- 이유: Railway 배포 전환의 핵심 목적 — 여러 기기·브라우저에서 동일한 학생 상태를 신뢰성 있게 공유하고, 서버측 트랜잭션(`SELECT ... FOR UPDATE`)으로 동시 거래 경쟁 조건을 막기 위함.
- 영향 범위: `server.js`(라우팅·거래로직), `lib/db.js`(스키마), 학생 상태를 다루는 모든 API 엔드포인트.
- 폐기 조건: 없음 (아키텍처 전환의 근간).

### 의존성은 pg 하나만 (2026-08-15, 사용자 명시)
- 결정: npm 의존성은 `pg`(node-postgres) 하나만 유지한다. 새 의존성 추가 금지 — Node 내장 모듈(crypto/http/fs)로 해결.
- 이유: 순수 Node.js·프레임워크 없음이라는 프로젝트 정체성 유지. 공급망 취약점 표면 최소화(교육기관용 앱의 보안 요구사항).
- 영향 범위: `package.json`, 전체 서버 코드.
- 폐기 조건: 사용자 재승인 없이는 변경 불가.

### 학급 코드/닉네임/PIN 인증 방식 (2026-08-15, 사용자 명시)
- 결정: 학생 로그인은 학급 코드(class_code) + 닉네임(nickname) + PIN(scrypt 해시 저장) 조합으로 한다. 실명·학번 등 개인정보는 수집하지 않는다.
- 이유: 초등학생 대상 서비스의 개인정보 최소 수집 원칙. 닉네임+PIN만으로 간편하게 접속 가능해야 함.
- 영향 범위: `lib/db.js`(students/classes 스키마), `lib/auth.js`, `server.js` 로그인 라우트, `public/app.js` 로그인 UI.
- 폐기 조건: 없음.

### 운영 환경 fail-closed (2026-08-15, 사용자 명시)
- 결정: 운영 환경(NODE_ENV=production)에서 JWT_SECRET(32자 이상)·DATABASE_URL 등 필수 환경변수가 없으면 서버는 기본값으로 대체하지 않고 즉시 종료(exit 1)한다.
- 이유: 약한 기본값·비밀 누락 상태로 조용히 기동되는 것을 방지 — 학생 계정·잔액 데이터의 무결성 사고 예방.
- 영향 범위: `server.js` 부팅 시퀀스(`ensureEnv`/`loadEnv` 이후 검증 블록), `lib/auth.js`.
- 폐기 조건: 없음.

### JWT_SECRET 운영 중 회전 금지 (2026-08-15, 사용자 명시)
- 결정: 운영 중인 JWT_SECRET을 임의로 회전(교체)하지 않는다.
- 이유: 회전 시 발급된 모든 토큰이 무효화되어 전 사용자(학생·교사)가 강제 로그아웃된다 — 수업 중 서비스 중단으로 이어짐.
- 영향 범위: `lib/auth.js`, Railway 환경변수 운영.
- 폐기 조건: 보안 침해로 즉시 회전이 불가피한 경우에만, 사용자 승인 후 전 사용자 재로그인 공지와 함께 진행.

### `.stocksave` 백업 형식 폐지 (2026-08-15, 사용자 명시)
- 결정: 기존 클라이언트 로컬 AES-GCM 암호화 + `.stocksave` 백업 파일 다운로드 기능은 v3(Postgres 전환)에서 사용을 종료한다. 상태는 서버가 정본이므로 로컬 백업 파일 복원 경로가 더 이상 필요 없다.
- 이유: 서버측 JSONB 정본 결정과 상충 — 로컬 백업이 서버 상태와 어긋나면 혼란만 유발.
- 영향 범위: `public/app.js`(백업/복원 버튼·`indexedDB`/`crypto.subtle` 사용 경로), `README.md`.
- 폐기 조건: 없음(제거가 최종 형태).

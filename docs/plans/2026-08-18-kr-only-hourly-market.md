# [SUPERSEDED] 국내 주식 전용 시세 계획 — 일별 OHLCV·일봉 차트로 전환

> 이 파일명은 기존 링크 보존을 위해 유지한다. 2026-08-18 계획의 짧은 시세 확인 주기와 시간봉 가정은 폐기되었다. 2026-08-21부터 금융위원회 `주식시세정보`의 실제 제공 단위인 **일별 OHLCV**, **하루 1회 새 자료 확인**, **30·90·180일 범위의 일봉 차트**가 현재 계획이다.

## 0. 스펙

- **목적**: 기존 Postgres/JWT 기반 온라인 학생 계정과 국내 주식 전용 거래 구조를 유지하면서, 공식 일별 OHLCV로 정확한 종목 차트를 제공하고 Railway에 안전하게 배포한다.
- **공식 데이터 범위**: 기준일, 종목코드·명, 시장구분, 시가·고가·저가·종가·거래량 등 일별 자료다. 시간봉이나 장중 실시간 시세가 아니다.
- **갱신 규칙**: 서버는 한국시간 14:10에 새 자료를 하루 1회 확인한다. 이 시각 뒤 재시작해도 당일 확인을 건너뛰지 않고, 일시적 오류는 30분 뒤 제한적으로 재시도한다. 공식 자료는 기준일 다음 영업일 오후 1시 이후 반영될 수 있으며, 주말·공휴일에는 최신 기준일이 더 이전일 수 있다.
- **차트 범위**: 학생 종목 상세 화면에서 최근 30·90·180일 범위의 일봉을 선택해 본다. 휴장일에는 봉을 만들지 않고 각 봉은 공식 시가·고가·저가·종가와 거래량만 사용한다.
- **배포 구조**: 애플리케이션 서버와 Postgres는 Railway를 사용한다. 운영 비밀값은 Railway Variables로만 주입한다.
- **제약**: 학생 상태의 정본은 Postgres JSONB다. 기존 인증·거래 트랜잭션·교사 관리 기능과 npm 의존성 `pg` 하나 원칙을 유지한다.
- **범위 밖**: 비공식 시세 수집, 임의 가격 생성, 일별 값을 시간봉으로 재구성, 새 장중 시세 공급자 도입, 구버전 학생 상태 이관.

## 1. 성공 기준

- 국내 6자리 종목코드와 KOSPI·KOSDAQ·KONEX만 검색·조회·거래할 수 있다.
- 시세 API와 캐시는 금융위원회 일별 OHLCV와 실제 기준일을 반환한다.
- 차트 API와 UI에서 최근 30·90·180일 범위의 일봉을 선택할 수 있다.
- 서버의 공식 데이터 확인은 하루 1회이며, 같은 기준일의 자료를 중복 시계열로 만들지 않는다.
- 화면에 공식 출처와 기준일을 표시하고, 장중 실시간 또는 시간봉이라는 표현을 사용하지 않는다.
- Railway Variables에 `DATABASE_URL`, `JWT_SECRET`, `ADMIN_PASSWORD`, `PUBLIC_DATA_SERVICE_KEY`를 설정할 수 있다.
- API 키·비밀번호·학생 데이터·Postgres 접속정보·시세 캐시가 Git 추적 파일과 전달 ZIP에 없다.
- 모든 테스트와 보안검사를 통과한 출시 파일만 명시적으로 스테이징되어 `main`에 fast-forward 푸시된다.

## 4. Railway와 비밀정보

- Railway 웹 서비스에 Postgres를 추가하고 `DATABASE_URL`은 서비스 참조 변수로 주입한다.
- `JWT_SECRET`, `ADMIN_PASSWORD`, `PUBLIC_DATA_SERVICE_KEY`, 선택적 `TEACHER_MASTER_PASSWORD`의 실제 값은 Railway Variables에만 둔다.
- `.env.example`은 변수 이름과 가짜 예시만 제공하며 실제 값을 담지 않는다.
- `.env`, API 키 파일, 비밀번호 파일, 학생 상태·거래 내역, `data/kr-public-prices.json`, 로그, `runtime/`, `node_modules/`는 Git과 ZIP에서 제외한다.
- Railway 컨테이너의 시세 캐시는 재생성 가능한 런타임 자료이며 학생 데이터의 정본이 아니다. 학생 데이터는 Railway Postgres에만 저장한다.

## 5. 버전별 검증과 푸시

1. 구문, 국내 전용, 플레이스홀더, 인증, DB·서버 스모크 검사를 실행한다.
2. 실제 로컬 비밀값이 추적 파일이나 staged diff에 포함되지 않았는지 값 역검색으로 확인한다.
3. 학생 데이터·시세 캐시·로그·런타임·의존성 폴더가 Git 추적 목록과 ZIP 목록에 없는지 확인한다.
4. `git add -A`를 사용하지 않고 이번 버전의 승인된 파일 경로만 명시적으로 스테이징한다.
5. staged diff를 다시 검토하고 커밋한 뒤 `main`에 force 없이 fast-forward 푸시한다.
6. `origin/main`과 로컬 커밋 SHA가 같은지 확인하고, 그 커밋에서 `git archive`로 ZIP을 만든 뒤 내용과 SHA-256을 검증한다.

## 7. 리스크와 복구

- 공식 자료가 장중 가격보다 늦음 → 출처와 기준일을 항상 표시하고 시간봉·실시간으로 오인시키지 않는다.
- 다음 영업일 오후 1시 이후에도 공급자 반영이 지연됨 → 마지막 정상 캐시를 유지하되 기준일을 그대로 노출한다.
- 휴장일을 가격 0 또는 가짜 봉으로 채울 위험 → 실제 응답이 있는 거래일만 일봉으로 사용한다.
- Railway 재배포로 로컬 캐시가 사라짐 → 공식 데이터에서 재생성한다. 학생 상태는 Postgres에 있어 영향받지 않는다.
- 릴리스에 비밀값이나 학생 데이터가 섞일 위험 → 테스트·역검색·추적 목록·ZIP 목록 검사를 통과하지 못하면 푸시하지 않는다.
- 복구는 과거 시장 구조나 짧은 갱신 주기를 되살리지 않고 국내 일별 OHLCV 기준에서 수정하는 fix-forward 방식으로 진행한다.

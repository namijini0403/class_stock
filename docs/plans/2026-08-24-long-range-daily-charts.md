# 장기 일봉 차트 계획 — v3.2.0

## 0. 스펙

- **목적**: 학생이 종목 상세에서 금융위원회 공공데이터의 일봉을 최근 1개월(`1m`)·3개월(`3m`)·6개월(`6m`)·1년(`1y`)·3년(`3y`)·5년(`5y`)·10년(`10y`) 범위로 선택해 볼 수 있게 한다.
- **범위 밖**: 시간봉·장중 실시간 시세, 수정주가 추정, 외국 주식, 운영 비밀값 또는 학생 데이터의 파일 저장은 추가하지 않는다.
- **제약**: 기간은 한국시간 오늘을 기준으로 달력 월·년을 계산한다. 휴장일에는 봉을 만들지 않는다. 공식 API는 하루 1회 갱신되고 자료는 기준일 다음 영업일 오후 1시 이후 반영될 수 있으므로, 서버는 한국시간 14:10에 하루 1회 새 자료를 확인한다. API 호출 한도, Railway 메모리, 모바일 SVG 노드 수를 보호한다. 실제 제공 이력이 짧거나 신규 상장 종목이면 확보 가능한 상장 이후 기간만 사실대로 표시한다.
- **표시 의미**: 장기 OHLCV는 수정주가가 아닌 금융위원회 원시 시세다. 화면 폭 때문에 여러 거래일을 묶을 때 첫 시가·최고 고가·최저 저가·마지막 종가·거래량 합계를 사용하며, 최초·최종 종가 변화는 투자수익률로 표시하지 않는다.
- **성공 기준**: 7개 기간을 선택할 수 있고, 500행 초과 이력이 안전하게 페이지 조회되며, 실제 HTTP 페이지 수만큼 호출 예산이 계산된다. 짧은 범위부터 긴 범위로 확장할 때 기존 캐시를 병합하고, 10년 원본 일봉은 요약에 유지하면서 화면에는 읽을 수 있는 수의 OHLCV 구간만 그린다.

## 1. 현황 조사

- v3.1.0은 30·90·180일 버튼과 최대 365일 캐시를 제공한다.
- `fetchKrHistory()`는 `totalCount > 500`을 거부해 현재 다중 페이지 코드가 실질적으로 동작하지 않는다.
- 호출 예산은 논리 요청당 1회만 차감해 다중 페이지의 실제 호출 수를 과소계상한다.
- 캐시는 종목당 하나지만 조회 완료 범위를 기록하지 않아 범위 확장과 최근 구간 갱신을 구분할 수 없다.
- SVG는 모든 일봉을 개별 DOM 노드로 그리므로 약 2,500개인 10년 이력을 그대로 렌더링하면 모바일에서 겹치고 느려진다.
- 공식 명세는 일 1회 갱신·T+1 영업일 오후 1시 이후·개발계정 10,000회/일을 밝히지만, 종목별 장기 보유 범위와 수정주가 여부는 보장하지 않는다.

## 5. 리스크·롤백

- 공식 API가 일부 종목의 10년 이력을 제공하지 않을 수 있음 → 요청 범위와 실제 최초 제공일을 분리해 표시하고 확보 가능한 이력만 보여 준다.
- 액면분할 등으로 장기 원시 가격이 투자수익률처럼 오해될 수 있음 → 수정주가가 아닌 공식 원시 시세이며 요약은 단순 종가 변화임을 화면에 표시한다.
- 긴 이력이 Railway 메모리를 압박할 수 있음 → 종목 수와 총 bar 수를 함께 제한하는 LRU를 사용한다.
- 롤백: v3.2.0 단일 커밋을 되돌리면 v3.1.0의 30·90·180일 차트 계약으로 복구된다. DB 스키마 변경은 없다.

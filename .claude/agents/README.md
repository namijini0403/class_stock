# 우리학교 모의투자 에이전트 팀 — 협응 규칙 (오케스트레이터용)

> 에이전트 정의 파일은 `docs/templates/agent-template.md`를 이 폴더로 복사해 만든다.

메인 모델(오케스트레이터)이 도메인별 전문 서브에이전트에게 작업을 위임한다. CLAUDE.md §0의 확장.
**오케스트레이터(메인) 독점**: 계획·설계 결정·**검증 통과 판정·도메인 정확성 판단·커밋/머지/푸시·충돌 중재**. 절대 위임 금지.
(감사·스캔·테스트의 **실행**은 위임 가능 — 최종 **판정**만 메인이 한다. 검수관류 read-only 에이전트가 그 예.)

## 별명 ↔ 에이전트 (호출용)

| 별명 | 에이전트(`name`) | 한 마디 |
|---|---|---|
| 수문장 | security-auditor | 보안·개인정보 감사 (packs/security-privacy 참조), 읽기전용 |

## 소유권 경계 (병렬 충돌 방지 — 이게 핵심)

에이전트마다 **편집 가능한 파일 glob**을 명시한다. 경계 밖 파일이 필요하면 STOP + 보고.
경계가 겹치지 않는 에이전트끼리만 병렬 가동.

| 에이전트 | 소유(편집 가능) | 비고 |
|---|---|---|
| 메인 모델 | `server.js`, `lib/**`, `public/**` | 라우팅·거래로직·프론트엔드 전부. |
| security-auditor | `docs/security/**` | 코드는 **감사만**(지적 → 메인이 수정). auth/DB 코드 경로(`server.js` 인증 섹션, `lib/db.js`, `lib/auth.js`)는 절대 편집 금지 — 읽고 지적만. |

## ⚠️ 공유·순차 파일 (절대 병렬 금지 — 오케스트레이터가 순차 디스패치)

- `server.js` — 라우팅·거래로직 전부가 이 한 파일에 있다. 동시 편집 금지, 순차 디스패치.
- `lib/db.js` — 스키마 정본(부팅 시 CREATE TABLE IF NOT EXISTS). 여러 에이전트가 동시에 건드리면 마이그레이션 충돌.

## 핸드오프 프로토콜

- security-auditor → 메인: 감사 결과는 `docs/security/`에 보고서로 남기고, 발견 사항은 메인(또는 메인이 지정한 코드 오너)이 수정. security-auditor는 절대 `server.js`/`lib/**`/`public/**`를 직접 고치지 않는다.
- 새 API 엔드포인트·DB 정책 추가 시: 병합 전 security-auditor 감사 1회 권장.

## 모든 서브에이전트 공통 규약 (각 정의에 내장할 것)

1. **커밋·푸시 절대 금지** (오케스트레이터 전담).
2. **소유 경계 밖 파일 편집 금지** — 필요 시 STOP + 보고.
3. **공유 순차 파일 단독 편집 금지** — 오케스트레이터에 요청.
4. **자체 검증 루프**(CLAUDE.md §3)로 통과까지 자기수정. 단 **최종 게이트·도메인 정확성 인증은 오케스트레이터**.
5. 완료 보고: 변경 파일 목록 · 테스트 명령+출력 · 자체검토 결과 · 미해결 우려.
6. 해당 도메인 불변식(각 정의에 전문 수록) 위반 = 실패.
